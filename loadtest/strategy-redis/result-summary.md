## 해석 및 제한사항

- 적용 전에는 서로 다른 시세 이벤트가 모두 같은 BUY 조건을 만족해 요청마다 Kafka Signal이 발행됐다.
- 적용 후에는 최초 요청 한 건만 Signal을 발행하고 나머지 9,999건은 Redis 상태 머신에서 차단됐다.
- 적용 후 처리량과 응답시간 개선은 Lua 명령 자체가 HTTP 처리를 빠르게 만든 결과가 아니라, 불필요한
  Kafka 동기 발행 9,999건을 제거해 요청별 작업량이 감소한 결과로 해석해야 한다.
- 정확한 전후 공통 기준은 Kafka Topic end offset 증가량이다. `9cb640b9`에는
  `strategy_signal_published_total`, `strategy_signal_duplicate_blocked_total` 메트릭이 아직 없어
  해당 카운터의 전후 비교는 수행하지 않았다.
- 적용 전 revision `9c01162c`는 Listener가 아직 존재하지 않는 `clearSignalState()`를 호출해 원본 그대로는
  컴파일되지 않았다. 테스트용 worktree에 조건 상태를 변경하지 않는 no-op 메서드만 추가했다. 이 보정은
  적용 전의 Signal 발행 로직과 Redis 이벤트 멱등 처리에는 영향을 주지 않는다.
- 이 결과는 단일 market-service 인스턴스의 전략 평가 단계까지만 검증한다. Redis와 Kafka를 하나의
  트랜잭션으로 묶거나 Trading Service 및 KIS 주문 실행의 Exactly-once를 보장하는 결과가 아니다.
